# シフト送信のしくみ（設定手順）

スマホの `shift.html` から送った内容を、シフト表のスプレッドシートに直接書き込むための設定です。
**エンジニアでなくてもできます。10分ほどで終わります。**

```
スマホ（shift.html）  ──送信──▶  Apps Script（shift-api.gs）  ──書き込み──▶  シフト表
                                                              └─記録──▶  送信ログ
```

対象スタッフ：**福岡・清田・福山・古川**

## 大事な前提：独立したスクリプトとして作る

シフト表のスプレッドシートには、パートナー様フォーム用の Apps Script が
すでに紐づいている可能性があります。そこへ貼り足すと `doPost` などの名前が
ぶつかって**両方とも動かなくなる**ため、**別の独立したプロジェクト**として作ります。

書き込み先は `shift-api.gs` の `SHEET_ID` で指定済みです（シフト表のID）。
既存のスクリプトには一切触れません。

---

## 1. 新しいスクリプトを作る

1. ブラウザで <https://script.new> を開く（シフト表を持っているGoogleアカウントでログインしていること）
2. 最初から入っている `function myFunction() {}` を**全部消す**
3. このフォルダの **`shift-api.gs` の中身をすべてコピーして貼り付け**
4. 左上のプロジェクト名（「無題のプロジェクト」）を **`Sieg シフト送信API`** に変更
5. フロッピーマーク（保存）を押す

`SHEET_ID` と `TOKEN` は入力済みなので、コードを書き替える必要はありません。

## 2. ウェブアプリとしてデプロイする

1. 右上の **「デプロイ」→「新しいデプロイ」**
2. 左の歯車マーク → **「ウェブアプリ」** を選ぶ
3. 設定を次のようにする
   - 説明：`シフト送信API`
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」を押す
5. **アクセスを承認**する
   （「アクセスを承認」→ アカウントを選ぶ → 「詳細」→「Sieg シフト送信API（安全ではないページ）に移動」→「許可」）
6. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/……/exec`）をコピー

## 3. shift.html にURLを貼る

リポジトリの `shift.html` を開き、`<script>` のいちばん上を書き替えます。

```js
var SHIFT_API = 'ここにGASのデプロイURLを貼る';   →   コピーしたURL
```

`SHIFT_TOKEN` は `shift-api.gs` の `TOKEN` と同じ値がすでに入っています。
保存してプッシュすると、数分後に GitHub Pages に反映されます。

## 4. 動作確認

- ブラウザで `……/exec?action=ping` を開き、`{"ok":true,...}` が出れば設置成功
- Apps Script の画面で関数 `testFindRows` を実行すると、**シフト表・日付の行・各スタッフの行が
  正しく見つかっているか**が実行ログに出ます（今月のシフト表を見ます）

## 直したいときは

| やりたいこと | 直す場所 |
|---|---|
| スタッフを増やす／減らす | `shift.html` の `STAFF`、`shift-api.gs` の `ALLOW_STAFF` |
| 取引先・キャリアの選択肢 | `shift.html` の `CLIENTS` / `CARRIERS` |
| よく使う開催場所 | `shift.html` の `PLACES` |
| 書き込み先のシートを変える | `shift-api.gs` の `SHEET_ID` |
| 送信ログのシートを固定したい | `shift-api.gs` の `LOG_SHEET_NAME` |

**コードを直したら、必ず「デプロイ」→「デプロイを管理」→ 鉛筆マーク → バージョンを
「新バージョン」にして更新してください。** これをしないと古いコードのまま動きます。

合言葉（`TOKEN`）は、URLだけを知った人の送信を防ぐための簡易的なものです。
ページのソースを見れば読めるので、本格的な認証ではありません。

## しくみのメモ

- シフト表の行・列は決め打ちしていません。A列からスタッフ名を探し、その下の
  `取引先` / `キャリア／店舗` / `開催場所` / `ホテル` の行を見出しで判別し、
  `日付` の行から日にちの列を探して書き込みます。行や列が増えても動きます。
- 集計レポートのシートは名前が似ていますが、「日付」の行があるかどうかで
  シフト表と区別しているので、間違って書き込むことはありません。
- 送信は連続した日を1件にまとめて（例：11日〜18日）ログに残ります。既存の
  「日時・操作・名前・年・月・開始日・終了日・取引先・キャリア・開催場所・ホテル」の
  ログシートをそのまま使います。
- 「取り消す」で送ると、その日のセルを空にして、ログには `削除` として残ります。
- 集計レポートのシートは更新しません（これまでどおりの更新方法のままです）。
